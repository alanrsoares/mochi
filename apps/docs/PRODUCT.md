# Product

## Register

product

## Users

JavaScript and TypeScript developers trying Mochi in a browser, comparing inferred
types and generated output, and editing small examples before adopting the language.

## Product Purpose

The playground makes language behavior visible: edit source, see its result,
inspect JS/TS/declarations, and fix compiler diagnostics. The landing page is a
brand surface; the playground is a tool within the same docs app.

## Brand Personality

Warm, practical, curious. Show useful working code and plain explanations, as
established in docs/docs-reframe.md and the reviewed examples.

## Anti-references

Decorative demos that do not demonstrate their claims; styling-heavy examples;
academic compiler jargon in onboarding; promotional badges presented as results.

## Design Principles

- Use real examples and real outputs.
- Put the result of the reader's edit within easy reach.
- Keep generated code and inferred types inspectable.
- Make setup and integration boundaries explicit.
- Keep controls predictable on desktop and mobile.

## Accessibility & Inclusion

Retain native form controls, meaningful accessible names, visible keyboard focus,
and labels for state changes. Support both existing color themes and narrow
screens. Do not invent a compliance claim that has not been audited.
